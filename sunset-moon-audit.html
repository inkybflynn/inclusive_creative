Fixes: accessibility

Accessibility means people with disabilities can use the site, including people who are blind and use a screen reader, people with low vision, and people who can’t use a mouse. Every page checked has at least one serious problem. Most come from the header and footer, which appear on every page, so fixing them once fixes every page.

The social media icons have no names

You can do this15 min
What’s wrong

The Facebook, YouTube, Patreon, Instagram and TikTok icons in the footer are pictures only. A screen reader just says “link” five times, so a blind visitor can’t tell where each one goes.

How to fix it
  1. In WordPress admin, open the Pro theme’s footer editor. In Pro this is usually under Pro → Footers.
  2. Click the Facebook icon to select it.
  3. Open the Customize tab for that icon and find Custom Attributes.
  4. Add an attribute. For Name, type aria-label. For Value, type a plain description, such as Sunset Moon Wellness on Facebook. This is called an ARIA label.
  5. Repeat for YouTube, Patreon, Instagram and TikTok, then save.

These steps follow Themeco’s support forum. If you can’t find Custom Attributes in your version, ask Themeco support where it is.

The booking, form and donation boxes have no names

You can do this15 min
What’s wrong

The Google Calendar booking box and the Google Form on Appointments, the Zeffy donation box on Donate, and the Google Form on Classes are embeds. None has a title, so a screen reader can’t say what each box is before a visitor enters it.

How to fix it
  1. Open the page in the Cornerstone editor and click the box that holds the embed code.
  2. Find the code that starts with <iframe.
  3. Right after <iframe, add a space and title="Book an appointment". Use a name that fits each box, such as title="Donation form" or title="Pay another way form".
  4. Save, then do the same for each embed.
Before: <iframe src="https://calendar.google.com/…"
After: <iframe title="Book an appointment" src="https://calendar.google.com/…"

Some headlines are hard to read

You can do this1–2 hrs
What’s wrong

White headlines sit on photos and light pastel backgrounds. The contrast measured 2.5 to 2.76. The minimum for readable text is 4.5, or 3 for large headlines. The homepage alone has 37 spots like this.

How to fix it
  1. Open the homepage in Cornerstone and click the section behind a hard-to-read headline.
  2. In the section’s background settings, add a dark color layer (an overlay) on top of the photo, or darken the gradient colors.
  3. Check your colors with the free WebAIM Contrast Checker. Enter the text color and the darkest background color behind it. Aim for “Pass” on WCAG AA.
  4. Repeat on other pages with text over photos.

Some pages have no main heading

You can do this30 min
What’s wrong

Every page should have one main heading, called an H1. Purification Programs, Classes and Naturopathy have none. Screen-reader users and Google both use the H1 to understand what a page is about.

How to fix it
  1. Open the page in Cornerstone and click the big title at the top (for example, “NATUROPATHY”).
  2. In its settings, find the heading level (often shown as a tag option such as H1, H2, H3) and choose H1.
  3. Make the words descriptive, such as “Naturopathic Consultations for Women”. Use only one H1 per page.
  4. On Classes, dates like “October 2026” are set as headings. Change them to regular text, bold if you like.

Images aren’t described

You can do this30 min
What’s wrong

Most homepage images have the description “Image”, which tells a blind visitor nothing. This description is called alt text. One homepage image is also broken and shows a 404 error.

How to fix it
  1. Go to Media → Library and click an image.
  2. In Alternative Text, describe what the image shows and why it matters, in one short sentence. For example, a photo of the practitioner could be “Megan Kelly, founder of Sunset Moon Wellness.”
  3. If an image is only decoration, leave Alternative Text empty rather than writing “Image”.
  4. For logos, use the organization’s name: “Sunset Moon Wellness Center”.

The W3C has a simple guide for deciding: An alt Decision Tree. The broken image is covered under Fix the Donate typo and the broken image.

Design guidance: make every page readable

The biggest design problem is words placed on top of photos and pastel color blends on almost every section. It looks soft and pretty, but much of the text is hard or impossible to read. The fix is simple: put words on plain backgrounds and let photos sit beside them.

These two examples are simplified drawings to show the idea, not screenshots of the site.

Seven design rules for this site

  1. Put words on plain backgrounds. Use a solid light color (white, cream or a very pale tint of the brand purple) behind all paragraphs and buttons. Photos go beside the text, above it, or below it, never behind it.
  2. Allow text on a photo only once per page. The top banner (the hero) can keep a photo with words on it, but only with a dark overlay so the words pass a contrast check. Keep it to a headline and one button.
  3. Use the pastel color blends as trim, not backgrounds. A thin band, a divider or a card edge keeps the brand feel without covering text.
  4. Write headings in normal capitals. Long headings in ALL CAPS are slower to read. “Purification Programs” reads more easily than “PURIFICATION PROGRAMS”.
  5. Pick three colors and stick to them. One dark color for text (a deep plum or near-black), one light color for backgrounds, and one strong color only for buttons. Check each text-and-background pair with the WebAIM Contrast Checker.
  6. Make body text big and left-aligned. Use at least 16-pixel text for paragraphs. Keep short headings centered if you like, but left-align paragraphs longer than two lines, which are easier to follow.
  7. Give each section one job and one button. Each section explains one thing and ends with one clear call to action, such as “Book a naturopathy session”. Leave generous white space between sections.

A simple layout for every service page

Use the same order on Naturopathy, Bodywork, Yoga and Doula Support, so visitors always know where to look.

  1. Headline (H1) that names the service and who it’s for.
  2. One sentence on what happens in a session.
  3. Format and price: online or in person, length, and the $65–$150 sliding scale.
  4. Book button that goes straight to Appointments.
  5. A real photo of Megan or the space, beside the text, with alt text.
  6. What to expect, in a short list.
  7. A testimonial, with permission.
  8. Questions and answers (see Add FAQ sections).

Fixes: search and AI visibility

SEO helps people find the site on Google. AEO helps AI assistants, such as ChatGPT or Google’s AI answers, understand and recommend it. The site already has Rank Math installed, which handles most of these fixes without code.

Search descriptions are too short or cut off

You can do this1–2 hrs
What’s wrong

The search description is the short summary under a page’s title in Google. Here, most are taglines such as “purify your life” or “learn expand explore”. The homepage description stops mid-sentence.

How to fix it
  1. Go to Pages and open a page for editing.
  2. Find the Rank Math box (below the editor or in the sidebar) and open Edit Snippet.
  3. Write one or two sentences (about 140–160 characters) that say what the page offers, who it’s for, and how (online or in person).
  4. Repeat for each page.
Example for Naturopathy: “Naturopathic, iridology and herbal consultations for women, online or in person. Donation-based sessions on a $65–$150 sliding scale.”

Google’s guide: How to Write Meta Descriptions.

The search engine instructions file slows Bing down

You can do this15 min
What’s wrong

The robots.txt file tells search engines how to visit the site. It asks them to wait 60 seconds between pages, which slows down search engines that obey it, such as Bing. It also doesn’t point to the sitemap.

How to fix it
  1. Go to Rank Math and switch on Advanced Mode (top right).
  2. Open General Settings → Edit robots.txt.
  3. Delete the line crawl-delay: 60.
  4. Add this line at the end: Sitemap: https://www.sunsetmoonwellnesscenter.com/sitemap_index.xml
  5. Save.

If Rank Math says it can’t edit the file, there is a separate robots.txt file on the server. Ask your host to make the change. Source: Rank Math robots.txt guide.

Google and AI tools don’t know what kind of business this is

You can do thisHalf a day
What’s wrong

Behind the scenes, pages carry labels called structured data. Right now, service pages are labeled as “articles”, like blog posts. There are no labels saying this is a nonprofit wellness center, what services it offers, or when classes happen. There’s also no address or service area on the pages checked, which matters for local search.

How to fix it
  1. Decide whether sessions have a public address, or are online only. This decides the business type.
  2. Go to Rank Math → Titles & Meta → Local SEO. Fill in the organization name, logo, phone, email, address (if public) and social media links.
  3. Open each service page (Naturopathy, Bodywork, Yoga, Doula Support) for editing. In the Rank Math box, open the Schema tab and change the type from Article to Service, if your version offers it.
  4. For each class, add an Event schema with the date, time, price, and whether it’s online.
  5. Test a page with Google’s free Rich Results Test (search for it by name).

Some Rank Math schema options need the paid version. If an option is missing, it may be a Pro feature. Google explains the idea in Intro to structured data.

Fixes: security and plugins

The basics are in place: the site uses HTTPS, and card payments happen on the outside services, not on the site. A few gaps are best handled by your host or a developer.

Close the security gaps

Ask your web hostPart is you1 hr
What’s wrong
  • Anyone can see a list of the site’s WordPress user accounts through a public API. That helps attackers guess login names.
  • The site tells visitors exactly which version of PHP it runs, which helps attackers look for known weaknesses.
  • A few recommended security headers are missing.
  • A plugin exposes an MCP connection to the public. It may be intended, but someone should confirm what installed it.
How to fix it
  1. You: make sure every admin account uses a strong, unique password and two-factor login.
  2. You: keep WordPress, the Pro theme and all plugins up to date (Dashboard → Updates). Back up first.
  3. You: go to Plugins and look for anything mentioning MCP, AI or “abilities” that you don’t recognize. Note its name before changing it.
  4. Your host: send them the message below.
“Could you please (1) block public access to the WordPress users list at /wp-json/wp/v2/users, (2) hide the X-Powered-By header that shows our PHP version, and (3) add Referrer-Policy and Permissions-Policy headers? We’d also like advice on adding a Content-Security-Policy that won’t break our Google Calendar, Zeffy and MailerLite embeds.”

Why LearnPress and MemberPress didn’t work

Ask your web hostMaybe a developer
What we know

Neither plugin is running on the site now. The site runs WordPress 7.1.2 and PHP 8.4.25, which meet both plugins’ published requirements. The exact cause can only be seen from inside WordPress admin and the host’s error logs. Three things are likely involved:

  1. Speed plugin conflicts. WP-Optimize caches pages and bundles scripts. MemberPress states its paywall features don’t work with page caching turned on. Bundled scripts often break course and membership features, which fits “embeds not working”.
  2. Page builder mismatch. LearnPress is designed around the WordPress block editor and Elementor. This site is built with Cornerstone.
  3. Database settings. MemberPress requires MySQL 8.0 or newer with certain strict settings turned off. Only the host can check this.
How to find the real cause
  1. Screenshot the exact “incompatible” message, and note when it appeared: while installing, while activating, or on a page.
  2. Go to Tools → Site Health → Info and click Copy site info to clipboard. Paste it into a document to share with your host or developer.
  3. Ask your host for a staging site (a private test copy) and for the PHP error log.
  4. On the staging site only: turn off WP-Optimize’s caching and script settings, then install the plugin again.
  5. If it still fails, switch the staging site to a default WordPress theme. If it works then, the problem is between the plugin and the Pro theme. Bring that to Themeco or a developer.
Something to consider first

Classes already run on Eventbrite, and membership on Patreon. Adding a course plugin (LMS) and a membership plugin means two large new tools to maintain and keep secure. If online courses are the goal, compare a hosted course platform linked from the site before spending more time on plugins.

Addendum: glossary

Plain definitions of the terms used in this report, in alphabetical order.

404 error
What a browser shows when a page or image can’t be found. Usually caused by a deleted file or a mistyped link.
Accessibility
Designing a website so people with disabilities can use it, whether they are blind, have low vision, are deaf, or can’t use a mouse. It also tends to make the site easier for everyone.
AEO (answer engine optimization)
Making a site easy for AI assistants and search “answer boxes” to understand and quote. Clear questions and answers, plain facts, and structured data all help.
Alt text
A short written description of an image. Screen readers read it aloud, and it shows if the image fails to load. W3C guide.
API
A behind-the-scenes doorway that lets software talk to the website. WordPress has one built in. Some parts of it share more than they should unless restricted.
ARIA label
A hidden name added to a button or link so screen readers can announce it. Visitors can’t see it, but screen-reader users hear it.
Automated accessibility scan (axe)
A free tool, axe-core, that checks a web page against accessibility rules. It finds many common problems but not all, so a person should also test the site.
Backup
A saved copy of the whole site (pages, images and settings) that can be restored if something breaks.
Caching
Saving a ready-made copy of each page so it loads faster. It can cause problems for features that must be different for each visitor, such as member-only content.
Call to action (CTA)
A button or link that asks the visitor to do one specific thing, such as “Book a session” or “Register”.
Contrast (contrast ratio)
How much text stands out from its background, as a number. Normal text needs at least 4.5; large text needs at least 3. Check colors with the WebAIM Contrast Checker.
Conversion
When a visitor does what you hoped, such as booking, donating or registering.
Cornerstone
The drag-and-drop page editor that comes with the Pro theme. It’s where most page content on this site is edited.
EIN (tax ID)
The federal tax ID number for an organization. Donors sometimes want it for their records.
Embed (iframe)
A box on a page that shows content from another website, such as a Google Calendar or a donation form. The technical name is iframe.
Google Analytics (GA4)
Google’s free tool for seeing how many people visit the site and what they do there. The site already has Google Tag Manager installed, which works with it.
Heading (H1, H2, H3)
Titles that organize a page, like an outline. H1 is the main title, used once per page. H2s are sections, and H3s are sub-sections.
Hero
The large banner at the top of a page, usually with a big image and headline.
HTTPS
A secure connection between the visitor and the website, shown by the padlock in the browser. This site has it set up correctly.
Link text
The clickable words of a link or button. Good link text says where it goes (“See class schedule”) rather than “click here”.
LMS (learning management system)
Software for selling and running online courses. LearnPress is one example.
Local search (NAP)
How a business shows up in “near me” searches and maps. It depends on a consistent name, address and phone number (NAP) across the web.
MCP
Short for Model Context Protocol, a way for AI tools to connect to software such as WordPress. If it wasn’t set up on purpose, it should be reviewed.
Meta description (search description)
The short summary Google may show under a page’s title in search results. Google’s guide.
Minifying and bundling scripts
Squeezing and combining the site’s code files so pages load faster. It sometimes breaks plugins that expect their files to load separately.
MySQL
The database where WordPress stores content and settings. Your host manages it.
Open Graph
Settings that control the image, title and description shown when a link is shared on social media or in a text message.
Overlay
A see-through layer of color placed over a photo so text on top is easier to read.
PHP
The programming language WordPress runs on. Your host controls which version the site uses.
Plugin
An add-on that gives WordPress new features, such as Rank Math for SEO. Each plugin needs regular updates.
Rank Math
The SEO plugin installed on this site. It manages search descriptions, sitemaps, robots.txt and structured data without code.
Responsive design
A site that rearranges itself to fit phones, tablets and computers.
robots.txt
A small text file that tells search engines which pages to visit and how often.
Screen reader
Software that reads a screen aloud for people who are blind or have low vision. Users often move through a page by jumping between headings and links.
Security headers
Instructions the server sends with each page that tell browsers to block certain attacks. Your host can add them.
SEO (search engine optimization)
Making a site easy for search engines like Google to find, understand and show to the right people.
Sitemap
A list of all the site’s pages that helps search engines find them. Rank Math creates it automatically.
Staging site
A private copy of the website for testing changes safely before they go live.
Structured data (schema)
Hidden labels on a page that tell Google and AI tools exactly what it is: a business, a service, an event, a FAQ. Google’s intro.
Theme (Pro theme)
The design framework that controls how the whole site looks. This site uses Themeco’s Pro theme, with a “child theme” that holds custom changes.
Two-factor login (2FA)
A second step when logging in, such as a code from your phone, so a stolen password alone isn’t enough.
Visitor path (user flow)
The steps a visitor takes to reach a goal, such as booking a session. Good paths are short and have no dead ends.
WCAG
Web Content Accessibility Guidelines, the international standard for accessible websites. Version 2.2 is current, and “AA” is the level most organizations aim for. W3C overview.
Web host
The company that runs the server the website lives on. They can help with backups, staging sites, server settings and error logs.
White space
Empty space around text and images. It makes a page feel calm and easier to scan.
WordPress admin
The private dashboard where you log in to edit the site.
